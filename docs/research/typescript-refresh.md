# TypeScript refresh tracker

<!-- typescript-refresh: last-verified=2026-11-04 typescript-version=7.0.2 -->

Living record of `typescript-guidance` (refresh mode) sweeps — the
per-facet, per-source state a run diffs against, so each sweep reports what
**changed** since the last one instead of rediscovering the whole toolchain
from scratch. Updated **in place** on every run, never as a new dated file.

`typescript-version` in the header records the newest **upstream**
TypeScript release the last sweep verified against — deliberately distinct
from `package.json`'s own `typescript` devDependency pin, which this
tracker exists to check against, not restate. The two numbers disagreeing
is not a bug in the tracker; it's the finding.

**2026-09-24 sweep** — first sweep. This repo's own toolchain (root
`tsconfig.base.json`, `packages/*/tsconfig*.json`, root `eslint.config.js`,
`vitest.config.ts`, `package.json`) is the domain graded here, not
`templates/core`'s baseline copy (which has its own `templates/core:typescript-guidance`
variant and is currently content-identical to root's `tsconfig.base.json`).
Upstream headline: TypeScript shipped a full native Go rewrite as 7.0 (stable
2026-07-08, latest patch 7.0.2 on 2026-08-20) — this repo is pinned to
`^6.0.3`, the last JS-codebase release line.

**2026-10-08 sweep** — second sweep, five parallel Explore spokes (one per
facet). Upstream delta: none. TypeScript 7.0.2 is still the latest release (only
`vscode-typescript/v1.0.1` landed, on 2026-09-30, bundling 7.0.2) and the newest
devblog post is still the 7.0 announcement (2026-07-08). `typescript-eslint` v9
has not shipped: v8.71.1 still supports TypeScript `>=4.8.4 <6.1.0`, so the
`^6.0.3` pin decision stands. Repo-side findings, remediated on
`fix/guidance-refresh-2026-10-08`: `templates/core/tsconfig.base.json` still
targeted `es2023` after the root moved to `es2025`; the root comment claimed the
per-package build projects set `isolatedDeclarations` when neither did; the
`check-exports.mjs` comment overstated attw's documented escape hatch;
`guard-no-commonjs.mjs` pointed at `fileURLToPath(import.meta.url)` instead of
`import.meta.dirname`; and Vitest 5's `.vitest/` report directory was not ignored.

**2026-10-19 sweep** — third sweep, five parallel Explore spokes (one per
facet). Upstream delta: no TypeScript release (7.0.2 is still latest; the
newest devblog post is still the 7.0 announcement, 2026-07-08), but the 7.1
Iteration Plan is public (microsoft/TypeScript#63703): Beta 2026-10-06 (late),
RC 2026-11-10, stable 2026-11-24, with a `release-7.1` branch cut on 2026-10-16
at `7.1.0-beta` and no tag yet. 7.1 ships the programmatic API that 7.0 lacks,
which is what typescript-eslint is waiting on. `typescript-eslint` is at 8.71.2
and still supports TypeScript `>=4.8.4 <6.1.0`, so the `^6.0.3` decision
stands. Repo-side findings (comments only, no flag or version change),
remediated on `fix/guidance-refresh-2026-10-19`: `consistent-type-imports`
overlaps `verbatimModuleSyntax`, Vitest's text-table comment overstated when
files are hidden, and attw's verdict follows its own bundled TypeScript.

**2026-10-20 sweep** — fourth sweep, run by `/customize` right after it adopted the harness-extras and github packs; five parallel Explore spokes, one per facet, every repo-impact claim re-checked against the cited file. Upstream delta: no TypeScript release (7.0.2 is still latest; the newest devblog post is still the 7.0 announcement). The `release-7.1` branch exists at `7.1.0-beta` (created 2026-10-16), but on 2026-10-20 there is still no 7.1 tag, no npm artifact reported and no beta post; the maintainers said on 2026-10-19 it was due "hopefully tomorrow", and the issue still lists the original RC and stable dates. `typescript-eslint` is now 8.72.0 with the same TypeScript range (`>=4.8.4 <6.1.0`), so the `^6.0.3` decision stands. No flag, version or config change was needed. **2026-10-22 sweep** — fifth sweep, run by `/customize` (adopt mode, third self-adoption pass); five parallel Explore spokes, one per facet, every repo-impact claim checked against the cited file. `typescript-version` stays at the newest **stable** release (7.0.2). Upstream delta: **TypeScript 7.1 Beta shipped on 2026-10-20** (devblogs post "Announcing TypeScript 7.1 Beta"; tag `v7.1-beta`, pre-release; the devblogs index lists the post under a wrong date). No flag, version or config change was needed and no repo file was edited from this sweep.
