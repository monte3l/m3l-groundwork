pack(harness-extras): `guard-readonly-bash` now judges a read-only agent's Bash command against an allowlist of read verbs instead of a denylist of mutating ones, because the denylist let real writes through. An off-list verb now blocks (`awk`, `python`, `gh`, `curl`, `make`, `tar`, `ln`, `install`, `patch`, `rsync`, a shell without `-c`, a verb built through expansion), as does an off-list git subcommand (`fetch`, `archive`, `submodule update`) or write flag (`git diff --output`, `git grep -O`), `node -e` or `-p`, `sed -ni`, `sed --in-pl`, `sed` scripts that use `w` or `e`, `sed -f`, `sort -o`, `uniq in out`, `find -fprint`, `find -exec` of an off-list command, and a command substitution that hides one (`echo $(rm x)`). The allowlist assumes the baseline's toolchain (`pnpm`, `npm`, `eslint`, `prettier`, `tsc`, `vitest`, `knip`, `publint`, `attw`): an adopted project on `yarn`, `make`, `jest` or `biome` should run its checks through a `package.json` script, since a read-only agent can no longer call those verbs directly. A script file run through `node`, `pnpm <script>` or `npm run <script>` is still not inspected, so the guard raises the bar and proves nothing. A project that already installed `harness-extras` keeps its copy of the hook untouched.
