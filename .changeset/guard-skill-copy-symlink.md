Installing the `/customize` skill no longer writes through a symlink and never removes or overwrites anything the project owns. Presence under `.claude/skills/customize/` is decided with `lstat`: an existing entry there (a differing copy, a project file under one of the skill's file names, a directory, or a symlink, dangling or not), or a `.claude`, `.claude/skills` or `.claude/skills/customize` that is a symlink or not a directory, sends the skill to `.groundwork/customize/` instead, and the CLI says why and what to do next (Claude Code does not load that copy). A symlinked `.groundwork` or `.groundwork/customize` still stops the install before the skill is written. `SKILL.md` is written last, and if a write fails, including a partial write, the CLI removes every file it created and says how many, so a half-installed skill is not left for Claude Code to load; a half-finished install left under `.claude/skills/customize/` is completed on the next run only when every leftover file matches this CLI version's copy byte for byte, and is otherwise left alone. Errors from the install say what happened and carry their cause.
