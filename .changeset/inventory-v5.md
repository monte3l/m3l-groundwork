Adopt mode now stages the baseline files it would add under `.groundwork/baseline/` as inert copies (each name gets a `.staged` suffix so no project tool or Claude Code discovers them as live source) and records each one's original path, staged name and SHA-256 in the inventory (`schemaVersion` 5, new `stagedBaseline` field). `/customize` no longer depends on `templateRoot`, an absolute path that may be gone by the time it runs: for a schema 5 inventory it checks that every staged file exists and matches its hash before offering anything, and stops with a re-run request otherwise, never falling back to `templateRoot`. The hash shows the staging is complete and matches the inventory, not that it is untampered. `/customize` also refuses an inventory newer than it understands, and refuses a `.groundwork/` directory that has no inventory (an interrupted run) instead of treating the project as fresh. Staging is atomic and refuses a symlinked `.groundwork`; the inventory is written last, atomically, so its presence means the run completed. A re-run also deletes the previous run's `adoption-decisions.json`, and the inventory and report are never written through a pre-existing symlink. `/customize` accepts only the exact staging directory and suffix, and rejects paths containing a backslash or a colon. `/customize` also stops on an inventory that is not valid JSON or has no usable `schemaVersion`. The CLI now prints the full cause chain of a failure, and a failed inventory or pack write says `.groundwork/` is incomplete and to re-run.
