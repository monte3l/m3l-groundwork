# design/ -- m3l-design, vendored

This directory is m3l-groundwork's copy of **m3l-design**, the shared design
system for everything Enrico Lionello (`enri3l`) builds personally and
everything published under the `monte3l` GitHub org.

- **Source:** [claude.ai/artifact/AyFoi7PNmQJXLyKUyBxHyk](https://claude.ai/artifact/AyFoi7PNmQJXLyKUyBxHyk)
- **Version copied:** `1790429550-bb17` (v1, signed off 2026-09-26)
- **Date vendored into this repo:** 2026-09-26

## Governance: copy-based, not a live dependency

m3l-design's own governance model (its brand book, `source/brand-book.md`,
under "Governance") is deliberate: **a single spec, copied into each
consuming project**, never an npm package a project imports live. This
repo's own `design/` is that copy. There is no `@monte3l/m3l-design`
dependency anywhere in this repo, and there never should be one -- adding
one would silently reintroduce the "live import" model the brand book
explicitly rejected, for the same reasons `m3l-groundwork` itself emits a
baseline into bootstrapped projects rather than having them depend on it.

## `source/` is vendored, verbatim -- never hand-edit it

Everything under `design/source/` is copied byte-for-byte from the
artifact above. If m3l-design ships a new version, re-sync it file by
file (never a wholesale overwrite that would also clobber `design/README.md`
itself), and record the new version id and date at the top of this file.

- `source/dtcg/*.tokens.json` and `m3l.resolver.json` -- the **canonical**
  DTCG 2025.10 token source. When `source/tokens.json` (below) and these
  files ever disagree, the DTCG files win -- see the brand book's "Token
  architecture" section for why.
- `source/tokens.json` -- m3l-design's own flattened copy, kept **only as a
  parity oracle**: `packages/cli/tests/design-tokens.test.ts` checks that
  `bin/lib/design-tokens.mjs`'s resolver reproduces every value in it. It is
  never read by anything this repo actually builds.
- `source/components/bundle.css` and `source/components/*/README.md` --
  the seven v1 components (Callout, CodeBlock, Badge, Button, Input, Card,
  Nav): plain HTML + CSS, no runtime, prefixed `m3l-`. Each README documents
  its markup, the tokens it uses, and its WCAG 2.2 AA contrast table.
- `source/foundations/contrast.md` -- every text/surface and UI/surface
  pairing, per theme, all passing WCAG 2.2 AA.
- `source/fonts/*.woff2` -- Atkinson Hyperlegible Next (sans) and Atkinson
  Hyperlegible Mono (code), both variable, weight 200-800, OFL-1.1 licensed
  (see `source/licenses/`). Chosen for character distinctiveness, which
  helps both dyslexia and dyscalculia accessibility -- see the brand book's
  "Typography" section.
- `source/brand-book.md` -- the full design brief and its "Built" record:
  personality, color system, typography, shape, motion, accessibility bar,
  token architecture, governance. Read this first for _why_ a token or
  component looks the way it does.

## What this repo generates from it

- `design/tokens.css` -- **generated, committed**, by
  `bin/build-design-tokens.mjs` from `source/dtcg/`. m3l-design's own format
  documents this file as something its artifact page would compile, but the
  artifact never actually publishes it (there is no upstream copy to
  vendor), so this repo builds it itself: light/dark custom properties
  (`prefers-color-scheme` and an explicit `data-theme` override, both), the
  non-color scale (space, radius, shadow, duration, easing, breakpoint,
  z-index, border-width, focus-ring, measure, the semantic `shape`/`inset`
  roles), `@font-face` rules pointing at `source/fonts/`, and one `.<style>`
  class per typography style (`.body`, `.label`, `.heading-1`, ...).
  `prefers-reduced-motion` zeroes every duration. A future terminal-output
  change (a `term.ts` painting `pnpm verify`'s TTY output in these same
  status colors) would extend this same generator with a
  `packages/cli/src/palette.ts` target rather than duplicating the color
  resolution -- not yet done, so no such file exists today.

`design/tokens.css` is regenerated by `node bin/build-design-tokens.mjs`,
and checked for drift by `node bin/build-design-tokens.mjs --check` --
wired into `pnpm verify`'s `lint` group as the `design-tokens` step.
**Never hand-edit it**; change `source/dtcg/` and regenerate instead.

## One open upstream flag

`source/brand-book.md`'s "v1 -- complete" section records one open token
decision, carried forward from m3l-design itself: in dark mode,
`color-surface-sunken` equals `color-surface-default` (both `neutral-1000`),
so a few components (Badge, Button, Input) borrow `color-surface-hover` as
an interim disabled/neutral fill. This repo inherits that as-is; fixing it
is an upstream m3l-design change, not something to patch locally in
`design/local/` (see below).

## `design/local/` -- reserved, currently empty

If this repo ever needs to diverge from upstream m3l-design (a token this
repo needs that the shared system doesn't have yet, a component variant
specific to this repo), that divergence goes in a new `design/local/`
directory, clearly separated from the vendored `source/` tree, rather than
edited into `source/` where a re-sync would silently discard it. Empty for
now -- this repo has needed no divergence yet.
